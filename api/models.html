Model Formulations

Implementation reference for the model formulation modules, including internal rule helpers. Each equation-bearing rule documents its implemented relationship in a NumPy-style Notes section, with symbol definitions and units.

Power is in MW and storage energy is in MWh. Time steps are implicitly one hour; dispatch sums therefore represent MWh. Annualized CAPEX and fixed O&M are annual costs, while variable costs accumulate over the modeled horizon without automatic annual scaling. The docstrings identify formulation-specific exceptions, such as the unscaled hydro energy budget and the unprorated storage cycle allowance.

For the full notation and formulation overview, see SDOM Formulation and Zonal Math Formulation.

System Formulations

Build copperplate system costs, net load, and energy-share constraints.

sdom.models.formulations_system.objective_rule(model)[source]

Return the copperplate investment-and-dispatch objective expression.

Parameters:

model (pyomo.core.base.block.BlockData) – Host with initialized VRE, storage, thermal, and trade cost expressions.

Returns:

Cost expression used by the minimizing objective.

Return type:

pyomo.core.expr.numeric_expr.NumericValue

Notes

\[Z=Z^{vre,fixed}+Z^{stor,fixed}+Z^{bal,fixed} +Z^{bal,var}+Z^{stor,var} +\sum_{h\in\mathcal H} (c^{imp}_h\iota_h-c^{exp}_h\xi_h).\]

Fixed terms include annualized CAPEX and annual fixed O&M (USD/year). Variable terms are modeled-horizon fuel and O&M costs (USD), with one-hour steps. \(\iota_h\) / \(\xi_h\) are imports / exports in MW; prices \(c^{imp}_h\) / \(c^{exp}_h\) are USD/MWh. Export revenue is subtracted. Variable costs are not rescaled for short horizons, so the total represents annual cost only for a full-year run. No hydro, nuclear, other-renewables, reserve, or curtailment cost is added.

sdom.models.formulations_system.net_load_rule(model, h)[source]

Return demand net of available VRE and fixed or scheduled generation.

Parameters:

  • model (pyomo.core.base.block.BlockData) – Host with initialized demand and resource expressions.

  • h (int) – Modeled hour.

Returns:

Net load in MW, before storage, thermal dispatch, and trade.

Return type:

pyomo.core.expr.numeric_expr.NumericValue

Notes

\[n_h=d_h-(G^{pv}_h+C^{pv}_h)-(G^{wind}_h+C^{wind}_h) -\alpha^{nuc}\nu_h-\alpha^{oth}\omega_h-G^{hyd}_h.\]

\(d_h\) is demand; \(G\) / \(C\) denote dispatched / curtailed VRE, whose sum is total_hourly_availability. Nuclear \(\nu_h\) and other-renewables \(\omega_h\) profiles are scaled by their alpha parameters. Hydro uses scheduled generation[h]. All power terms are MW. This is not residual demand after VRE curtailment.

sdom.models.formulations_system.create_supply_balance_rule(has_imports, has_exports)[source]

Create a copperplate supply-balance rule with optional external trade.

Parameters:

  • has_imports (bool) – Whether imports are included in the model.

  • has_exports (bool) – Whether exports are included in the model.

Returns:

Rule accepting a host and hour and returning a balance equality.

Return type:

function

Notes

At each hour \(h\), the returned rule enforces

\[\begin{split}\begin{aligned} d_h+\sum_j D^{ch}_{jh}+\xi_h ={}&\sum_j D^{dis}_{jh}+\alpha^{nuc}\nu_h+G^{hyd}_h +\alpha^{oth}\omega_h\\ &+G^{pv}_h+G^{wind}_h+\sum_kG^{bal}_{kh}+\iota_h. \end{aligned}\end{split}\]

All terms are MW. \(d\) is demand, \(D^{ch}\) / \(D^{dis}\) are storage PC / PD, and \(G\) is dispatched generation (not VRE availability). \(\nu\) / \(\omega\) are nuclear / other-renewables profiles with their activation scalars. \(\iota\) / \(\xi\) are imports / exports, omitted when disabled. This rule includes neither load shedding nor zonal line flows.

sdom.models.formulations_system.genmix_share_rule(model)[source]

Return the modeled-horizon clean-generation-share constraint.

Parameters:

model (pyomo.core.base.block.BlockData) – Host with thermal generation, demand, storage, GenMix_Target, and an imports block.

Returns:

The constraint expression for the generation mix target.

Return type:

pyomo.core.expr.relational_expr.InequalityExpression

Notes

\[\sum_{h\in\mathcal H}\sum_{k\in\mathcal K}G^{bal}_{kh} +\sum_{h\in\mathcal H}\iota_h \le(1-\tau)\sum_{h\in\mathcal H} \left[d_h+\sum_j(D^{ch}_{jh}-D^{dis}_{jh})\right].\]

\(\tau\) is GenMix_Target, \(d\) is demand, and storage charging/discharging are PC / PD. All power terms are MW; implicit one-hour sums are MWh. Imports count as non-clean and are omitted if imports.variable is absent. Exports are not subtracted from adjusted demand. The constraint is aggregate, not hourly.

sdom.models.formulations_vre._add_vre_parameters(block, set_hours, data: dict, key_filt_dict: str, key_filt_min_dict: str, key_comp_data: str, key_cf_data: str)[source]

Add plant costs, capacity limits, and hourly VRE capacity factors.

Parameters:

  • block (pyomo.core.base.block.BlockData) – PV or wind block with initialized plants_set.

  • set_hours (iterable) – Modeled hour indices.

  • data (dict) – Loaded inputs containing capacity mappings and plant/profile tables.

  • key_filt_dict (str) – Key for the plant-to-maximum-capacity mapping (MW).

  • key_filt_min_dict (str) – Key for the plant-to-minimum-capacity mapping (MW).

  • key_comp_data (str) – Plant-property table key; identifiers are in sc_gid.

  • key_cf_data (str) – Capacity-factor table key; its first column contains hour indices, and plant columns use string identifiers.

Notes

Missing plant cost properties default to zero. Missing capacity-factor entries do not receive a default. CAPEX_M is USD/kW, FOM_M is USD/kW-year, and trans_cap_cost is USD/MW.

sdom.models.formulations_vre.add_vre_parameters(host, data: dict)[source]

Add PV/wind parameters and their shared annualization factor.

Parameters:

  • host (pyomo.core.base.block.BlockData) – System or area with h and initialized PV/wind plant sets.

  • data (dict) – Loaded solar/wind capacities, costs, and capacity factors, plus scalars entries r and LifeTimeVRE.

Notes

For rate \(r\) and shared VRE lifetime \(l^{vre}\) in years,

\[a^{vre}=\frac{r(1+r)^{l^{vre}}}{(1+r)^{l^{vre}}-1}.\]

FCR_VRE stores \(a^{vre}\) in inverse years.

sdom.models.formulations_vre._add_vre_variables(block, set_hours)[source]

Add VRE dispatch, curtailment, and bounded investment fractions.

Parameters:

  • block (pyomo.core.base.block.BlockData) – PV or wind block with plant sets and capacity-limit parameters.

  • set_hours (iterable) – Modeled hour indices.

Notes

For generic VRE plant \(k\) and hour \(h\),

\[\begin{split}G_h,C_h\ge0,\qquad \underline F_k\le F_k\le1,\qquad \underline F_k= \begin{cases} \underline p_k/\bar p_k&\bar p_k>0,\\ 0&\bar p_k\le0. \end{cases}\end{split}\]

generation / curtailment are aggregate MW, not plant-indexed. capacity_fraction is continuous \(F_k\); min_capacity / max_capacity are \(\underline p_k\) / \(\bar p_k\) (MW). Dispatch and curtailment initialize to zero; fractions initialize to one.

sdom.models.formulations_vre.add_vre_variables(host)[source]

Add aggregate PV/wind dispatch, curtailment, and plant investment fractions.

Parameters:

host (pyomo.core.base.block.BlockData) – System or area with initialized PV/wind capacity parameters and h.

Notes

Each technology has hourly nonnegative generation and curtailment (MW). Plant investment is continuous between the minimum/maximum capacity ratio and one, with a zero lower fraction for nonpositive maxima.

sdom.models.formulations_vre._add_vre_expresions(block, fcr_vre, set_hours)[source]

Attach installed-capacity, availability, energy, and cost expressions.

Parameters:

  • block (pyomo.core.base.block.BlockData) – PV or wind block with initialized parameters and variables.

  • fcr_vre (float or pyomo.core.base.param.Param) – Shared capital annualization factor in inverse years.

  • set_hours (iterable) – Modeled one-hour indices.

Notes

For generic VRE plant \(k\),

\[\begin{split}\begin{aligned} P_k&=\bar p_kF_k,&P^{tot}&=\sum_kP_k,\\ A_h&=G_h+C_h,&E^G&=\sum_hG_h,&E^C&=\sum_hC_h,\\ Z^{cap}&=a^{vre}\sum_k(10^3\kappa_k+t_k)P_k,& Z^{FOM}&=\sum_k10^3\phi_kP_k. \end{aligned}\end{split}\]

max_capacity is \(\bar p_k\) (MW), capacity_fraction is \(F_k\), and plant_installed_capacity is \(P_k\) (MW). total_hourly_availability is \(A_h\) (MW), with dispatched \(G_h\) and curtailed \(C_h\); energy totals are MWh. \(a^{vre}\) is fcr_vre; CAPEX_M, trans_cap_cost, and FOM_M are \(\kappa_k\), \(t_k\), and \(\phi_k\) (USD/kW, USD/MW, USD/kW-year). Cost expressions are USD/year. Availability equals capacity-factor-weighted capacity only once the separate vre_balance_rule() constraint is attached.

sdom.models.formulations_vre.add_vre_expressions(host)[source]

sdom.models.formulations_vre.vre_balance_rule(block, h)[source]

Return the hourly VRE dispatch-plus-curtailment balance.

Parameters:

  • block (pyomo.core.base.block.BlockData) – PV or wind block with availability, capacity factors, and investments.

In zonal models, construct the network flows before adding the per-area capacity-margin constraints. sdom.models.formulations_reserves.add_capacity_margin_constraints(host, data: dict) → None[source]

Add CapacityMarginFormulation to a copperplate or area block.

Parameters:

  • host (pyomo.core.base.block.BlockData) – Owning system or area with initialized hourly resource components. For zonal areas, the parent model’s network flows must already exist.

  • data (dict) – Loaded inputs. Only the exact Reserves selection CapacityMarginFormulation enables this builder; otherwise it adds nothing (missing selection defaults locally to notModel). Optional capacity_marging_fraction is a global dimensionless fraction, defaulting to zero.

Raises:

ValueError – If the enabled margin is blank, nonnumeric, nonfinite, or negative.

Notes

For hour \(h\), storage \(j\), and cyclic predecessor \(h^{-}\), credit nonnegative deliverable storage capacity \(C^{stor}_{jh}\) (MW), represented by storage_capacity_contribution[h,j]:

\[0\le C^{stor}_{jh}\le P^{dis}_j,\qquad T^{adequacy}C^{stor}_{jh}\le\sqrt{\eta_j}S_{j,h^{-}}, \qquad T^{adequacy}=1\ \mathrm{hour}.\]

\(S\) is predecessor end-SOC (MWh), including last-hour SOC for the first hour; \(\eta\) is roundtrip efficiency. Installed energy capacity does not replace available SOC. Scheduled charge/discharge and the baseline mode binary do not enter these capacity bounds; same-hour charging cannot fund the contribution. This is credited supply capacity, not an upward dispatch award. No activated-output expression or defining equality is used.

The hourly capability requirement, in MW, is

\[\begin{split}\begin{aligned} &\sum_k P^{bal}_k+\sum_j C^{stor}_{jh} +\sum_p\sigma_{ph}\bar p^{pv}_p F^{pv}_p +\sum_w\zeta_{wh}\bar p^{wind}_w F^{wind}_w\\ &\quad+G^{hyd}_h+\alpha^{nuc}\nu_h+\alpha^{oth}\omega_h+N_h \ge(1+m)d_h. \end{aligned}\end{split}\]

Here \(m\) is the margin, \(d\) gross demand, \(P^{bal}\) installed balancing MW (full deterministic availability), and the VRE terms are contemporaneous capacity factors times installed MW. Charging is not added to gross demand or credited separately for interruption. Hydro is scheduled dispatch; nuclear and other renewables are scaled injections. \(N_h=0\) in copperplate mode. In zonal blocks it is scheduled net inflow \(N_h=\sum_{\ell\in\mathcal L_{in}(a)}f_{\ell h} -\sum_{\ell\in\mathcal L_{out}(a)}f_{\ell h}\). Existing signed flows credit imports and deduct exports; they cannot increase during activation. No additional reserve transfers or external imports are credited. Optional absent resources contribute zero. This is a one-hour capability proxy, not operating reserves or repeated-activation feasibility; no costs, shortfall slack, or baseline physics are changed.

Network (Zonal) Formulations

Network formulation (transportation model) for SDOM zonal mode.

This module implements the line topology, signed flow variable, directional capacity constraints, and reporting expressions for the AreaTransportationModelNetwork formulation (PRD §5.6).

Locked design decisions (PRD §5.6, 2026-05-08):

  • Topology lives on the top-level model (model.L, model.line_from, model.line_to, model.L_in[a], model.L_out[a]); per-area blocks consume but do not own it.

  • Capacity limits are imposed via explicit Constraint blocks (not Var bounds) so per-direction congestion shadow prices are exposed in the dual.

  • A single signed flow variable f[l,h] in Reals — no auxiliary binary, no f+/f- split; simultaneous bidirectional flow is impossible by construction of the bounds.

  • Z^trans = 0 placeholder (no transmission investment in this phase).

The zonal path in sdom.optimization_main.initialize_model() calls these builders on the root model; area balances consume the resulting signed flows.
