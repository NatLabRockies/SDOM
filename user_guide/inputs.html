SDOM Input Data

This page describes all input data requirements for running SDOM optimizations.

Input Data Structure

All input CSV files should be placed in a directory (e.g., Data/scenario_name/). File matching is case-insensitive and ignores spaces, hyphens, and underscores. Use the documented canonical filename stems so SDOM can identify each input file.

The following sections list each file and describe the data required in every field.

Each Main use (math) column links to the equation or constraint that mainly uses that input. Identifiers select model sets or profile columns; descriptions and geographic coordinates are metadata, not numerical equation coefficients. All hourly power profiles are in MW. Summing them over SDOM’s one-hour steps gives MWh. Preserve the CSV cost units below: the model converts USD/kW and USD/kWh inputs to the USD/MW and USD/MWh coefficients used in the math reference.

⚠️ Attention:

  • Make sure all required CSV files are present in the specified folder before starting the simulation.

  • Preserve the documented filename stem. For example, CapSolar_2025.csv must retain the CapSolar stem, though case and separators can vary.

  • Do not change required CSV column names.

Zonal Mode Inputs

SDOM supports two network formulations:

  • CopperPlateNetwork: legacy single-area system-wide balance.

  • AreaTransportationModelNetwork: multi-area zonal balance with inter-area transport limits.

For full zonal CSV schema, validation rules, and examples, see Zonal Inputs.

Large Hydropower

File: lahy_hourly.csv

This file provides the hourly generation time-series for hydropower plants. The way SDOM utilizes this data depends on the selected hydro formulation (formulations configuration):

  • RunOfRiverFormulation:
    Hydropower generation is directly set to the values specified in the time-series. No optimization is performed; the model simply follows the provided hourly profile.

  • Equality budgets (MonthlyBudgetFormulation or DailyBudgetFormulation): SDOM sums the reference profile over consecutive fixed periods: 24 hours for daily budgets and 730 hours for monthly budgets, not calendar months. The entire budget must be dispatched in each period; only its hourly allocation is optimized. Select these names for mandatory period-energy delivery.

  • Upper-bound budgets (MonthlyBudgetUpperBoundFormulation or DailyBudgetUpperBoundFormulation): The same period sums cap energy dispatch rather than requiring it. Select these names when unused hydro availability is allowed, including when retaining the recently relaxed behavior of the existing names.

    All four budget choices use the unscaled profile: AlphaLargHy scales the hourly minimum and maximum bounds, not the budget. Before solving, equality budgets are checked against both summed scaled minimum and maximum dispatch; upper-bound budgets are checked against the summed scaled minimum only. Availability above maximum possible generation is valid only for upper-bound budgets. These preliminary checks do not guarantee system-wide feasibility. Requested horizons round up to complete budget periods. Unused energy does not carry into later periods; no reservoir balance or slack is introduced. These budgets usually are outputs from long- and medium-term hydropower planning tools often based on Stochastic dual dynamic programming (SDDP). Examples of open-source tools for this are cobreand SimSEE

In summary, this file either serves as a fixed generation profile or as the basis for energy budgets, depending on the chosen hydro formulation. For budget formulations, reported hydro curtailment is unused period-budget energy, not an hourly reference-profile shortfall or necessarily physical water spill.

Data Validation

SDOM performs several validation checks during data loading:

  1. File Existence: All required files must be present

  2. Plant Consistency: Solar/wind plant IDs must match between CF and CAPEX files

  3. Completeness: Filters out plants with missing data (NaN values)

  4. Formulation Validity: Checks that specified formulations are valid

  5. Hour Count: For budget formulations, adjusts hours to be multiple of budget interval

Example Data Loading

from sdom import load_data

# Load data from directory
data = load_data('./Data/my_scenario/')

# Access loaded data
print(f"Number of solar plants: {len(data['solar_plants'])}")
print(f"Number of wind plants: {len(data['wind_plants'])}")
print(f"Storage technologies: {data['STORAGE_SET_J_TECHS']}")
print(f"Discount rate: {data['scalars'].loc['r', 'Value']}")

Tips for Data Preparation

  1. Consistent Plant IDs: Use string IDs for VRE plants (e.g., “101”, “202”)

  2. Hour Indexing: Use 1-based indexing (1-8760) for consistency

  3. Units: Stick to MW for power, MWh for energy, $ for costs

  4. File Naming: Use flexible naming (case doesn’t matter, underscores/hyphens optional)

  5. Missing Data: Remove rows/plants with incomplete data before running
